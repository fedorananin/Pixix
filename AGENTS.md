# Pixix

An image viewer and editor for macOS: it views like Windows 11 Photos and edits with layers like Paint.NET. Written by Fedor Ananin for his own Mac and published as open source under the MIT License at <https://github.com/fedorananin/Pixix>.

The design, its rationale and what is and is not finished are in [PLAN.md](PLAN.md). Read it before changing behavior. User-facing usage is in [README.md](README.md).

## Environment

This describes the author's machine, which is where development happens. The GitHub build uses the `xcode-27` runner image, which has the same compiler.

- macOS 27, Apple Silicon, Swift 6.4. Build target is macOS 26+, arm64.
- Xcode is not installed, only Command Line Tools. There is no `xcodebuild`, `actool` or `metal` compiler. Do not create an `.xcodeproj`, asset catalogs, or `.metal` files that rely on an Xcode build.
- The project and its git repository live in OneDrive. Nothing generated by a build may be written inside the project folder:
  - SwiftPM build directory: `~/Library/Caches/Pixix/build`, always passed as `--scratch-path`.
  - Assembled app: `~/Library/Caches/Pixix/dist/Pixix.app`.
  - Never create `.build` in the project. Put scratch files, sample images and screenshots under `~/Library/Caches/Pixix` too.

## Build and test

```sh
swift build --scratch-path ~/Library/Caches/Pixix/build
swift test --scratch-path ~/Library/Caches/Pixix/build
Scripts/build-app.sh             # release build, assembled and signed
Scripts/build-app.sh --install   # also copies the app to /Applications and makes it the default image viewer
Scripts/build-app.sh --install --keep-defaults   # installs without touching file associations
```

Installing changes which app opens images system-wide (`DefaultViewer.swift`); the previous apps are saved and `Pixix --restore-default` hands them back. Use `--keep-defaults` when only the binary needs replacing.

`build-app.sh` signs with the `Local Dev` certificate when the keychain has it, which is the case on the author's machine. Do not force an ad hoc signature there: it resets the macOS folder access permissions on every build. Without that certificate (on GitHub, on anyone else's Mac) the script signs ad hoc by itself.

## Layout

| Path | What it is |
|---|---|
| `Sources/CWebP` | Vendored libwebp 1.6.0. Only used to write WebP. Do not edit; replace wholesale to update. |
| `Sources/PixixCodec` | Reading, writing, metadata, the export pipeline. No UI, no actors. |
| `Sources/PixixEngine` | Document, layers, selection, history, Core Image renderer, painting. `@MainActor`, no AppKit windows. |
| `Sources/Pixix/App` | Launch, menus, settings, diagnostics. |
| `Sources/Pixix/Viewer` | The window, the canvas with zoom and gestures, folder browsing, image loading. |
| `Sources/Pixix/Export` | The export dialog and all saving. |
| `Sources/Pixix/Editor` | Editor controller, tools, inspector, dialogs. |

## Rules

- Closing the last window quits the app. This is the core requirement; do not break it.
- The "open a file, see the image" path must stay light. Nothing in it may touch the editor or libwebp. Measure with `--timing` (below) before and after changes to launch code; the first frame currently lands about 160 ms after process creation.
- Decoding and encoding run off the main thread and are cancellable.
- `PixixCodec` and `PixixEngine` do not depend on windows and are covered by Swift Testing tests. New engine behavior gets a test.
- `⌘S` overwrites the original file with an atomic write. `⌘⇧S` is Save As and leaves the original untouched.
- libwebp is the only third-party dependency. Do not add others without agreement.

## Things that will bite

- **`@State` does not compile here.** In the macOS 27 SDK it is a macro whose compiler plugin ships only with Xcode. Keep view state in an `@Observable` model (that plugin is in the Command Line Tools) and pass it in with `@Bindable`. The same goes for `@Entry` and `@Animatable`. `@Bindable`, `@Environment` and `@FocusState` are fine.
- **Swift Testing needs its plugin path spelled out.** `Package.swift` passes `-plugin-path` for the test targets; without it `swift test` fails intermittently with "plugin for module 'TestingMacros' not found".
- **Coordinates.** Document space is top-left origin, y down. Core Graphics and Core Image are y up. Conversions live in `Geometry.swift` and at the top of `Renderer.swift`; do not sprinkle new flips elsewhere. `PixelBuffer.withContext` hands out a context already flipped to y down, so images must be drawn with `drawUpright`.
- **Color.** `CGColor(red:green:blue:alpha:)` is Generic RGB, not sRGB, and gets converted when drawn. Use `RGBAColor.cgColor`. The renderer runs with color management off; pixel values pass through unchanged and the document's color space is attached on output.
- **Numbers in SwiftUI text.** `Text("\(width)")` formats the integer for the locale ("1 200"). Use `Text(verbatim:)` for pixel sizes.
- **Async overloads.** Inside a `Task`, `window.beginSheet(sheet)` resolves to the async variant. Pass `completionHandler: nil`.
- **Never run `--restore-default`, and never call the default-app APIs aimed at another app, to test something.** An app may claim a file type for itself silently, but `NSWorkspace.setDefaultApplication` and `LSSetDefaultRoleHandlerForContentType` pointed at a different app make macOS put a confirmation dialog on the user's screen for every type and wait for the answer. One restore run is about sixty dialogs. The command and the Settings button exist for the user to press; leave them alone.
- **Menu shortcuts without modifiers** would swallow typing in every text field. Tool shortcuts are handled in `EditorController.handleKeyDown`, not as menu key equivalents. `F2` is the exception, because it types nothing.
- **New fields in `TextContent`, `ShapeContent` and `EffectRegion` must be optional.** They are decoded from `.pixix` projects, and a project saved before the field existed has no key for it. A new enum case needs a bump of `ProjectFile.currentVersion`, so that older versions of the app say "saved by a newer version" instead of failing to read.
- **A text layer's box and what it paints are two things.** `Layer.frameBounds` is the box the handles go around; `localBounds` also takes in shadows and the tail of a speech bubble. Place text by `frameBounds`, and change text through `Layer.setText`, which keeps the box and the tail where they are.
- **Vision and VisionKit are linked but must not run before the first frame.** Linking them costs nothing at launch (measured); creating `LiveTextController` does, so it is made on the run loop turn after a picture is shown.

## Checking the interface without a person

The binary takes diagnostic switches, so changes to the UI can be verified from the terminal:

```sh
APP=~/Library/Caches/Pixix/dist/Pixix.app/Contents/MacOS/Pixix
$APP --timing --quit photo.jpg                           # milliseconds to first frame
PIXIX_TRACE=1 $APP --timing --quit photo.jpg             # with launch checkpoints
$APP --snapshot out.png photo.jpg                        # picture of the viewer window
$APP --snapshot out.png --edit --demo tools photo.jpg    # picture of the editor after a scripted scenario
```

Scenarios (`Sources/Pixix/App/Diagnostics.swift`), with `--edit`: `meme`, `tools`, `markup`, `text`, `layers`, `append`, `subject`, `cutout`, `save`, `crop`, `crop-applied`, `select`, `effect`, `export`, `menu`. `tools` drives every tool through the same entry points real mouse input uses. In the viewer, without `--edit`: `mouse` sends wheel and side-button events to the window and prints the zoom and the file after each one; `windows`, `files`, `livetext`, `info` and `menu` exercise what their names say and print what happened. Add a scenario when adding a tool or dialog, then look at the PNG. With a sheet or the Info popover open, that is what gets captured.

These runs are unattended, and must stay so: the author is usually at the machine while they run.

- A run with `--snapshot`, `--timing`, `--quit` or `--close` keeps its window off the screen and transparent, does not activate the app, and quits without asking about unsaved edits (`LaunchOptions.isUnattended`). A scenario must never end in a question to the user.
- `files` and `save` change the file they are given. Run them on a copy under `~/Library/Caches/Pixix/scratch`. `save` and the undo of `files` leave a file in the Trash; remove it afterwards.
- Put a time limit on every launch, for example `perl -e 'alarm 40; exec @ARGV' $APP …`, and check with `pgrep -lf Pixix` that nothing is left running.

Engine tests can also dump renders for inspection: set `PIXIX_TEST_OUTPUT` to a folder.

## Releasing

- The version lives in `Resources/Info.plist` (`CFBundleShortVersionString`) and nowhere else. Bump `CFBundleVersion` with it.
- Add a `## <version>` section to `CHANGELOG.md`; the release notes are cut from it.
- `.github/workflows/build.yml` tests and builds every push to `main` and every pull request. Pushing a tag `v<version>` also publishes a GitHub release with `Pixix.zip`. The tag must match the version in `Info.plist`, or the release job stops.
- The asset must stay named `Pixix.zip`: the install command in the README downloads `releases/latest/download/Pixix.zip`.
- Release builds are ad hoc signed and not notarized. The README tells users to clear the quarantine flag.
- Do not publish, push tags or create releases without being asked.
- Commit messages carry no co-author or tool attribution lines.
